# 抖音爆款拆解框架

用于 Phase 1:看抽帧图 + meta.json + beats.json,产出结构化拆解。拆解的价值不在"描述内容",而在抽出**可迁移到其他素材的结构**。

## 拆解维度

### 1. 开头钩子(0-3s,决定 5s 完播率)
归类到其中一种,并记录具体呈现:
- 悬念钩:抛问题不给答案("你绝对想不到结果")
- 冲突钩:对立观点/翻车现场前置
- 反常识钩:结论先行且违背直觉
- 视觉冲击钩:最炸的画面直接糊脸(全景视频常用:视角甩切/小行星开场)
- 身份代入钩:点名人群("大学生/新手爸妈注意")
- 结果前置钩:先放成果,再讲过程

### 2. 分镜节奏(逐段记录)
按抽帧逐段划分,记录每段:起止秒、时长、镜头内容一句话、景别/视角、字幕文本、是否在 beat 上切镜。
- 单段时长分布:爆款短视频常见 1.5-3s/段,超过 4s 无变化即流失点
- 切镜是否卡 beat:对照 beats.json 的 onset_peaks / beat_grid
- 信息密度:每 5s 是否有新信息/新画面/新情绪

### 3. 情绪曲线
按"能量值 1-10"给每秒打分(可参考 beats.json 的 energy_per_second),标记:
- 高潮点(能量峰值)出现位置:常见 60%-80% 进度处
- 低谷过渡段:是否用花字/音效/变速救场

### 4. 字幕与花字
- 有无全程硬字幕;字号、颜色、位置(底部居中/贴脸)
- 关键词高亮方式(变色/放大/描边)
- 花字出现时机(强调/吐槽/补信息)

### 5. 声音设计
- BGM:类型(卡点神曲/情绪铺垫/静音留白)、BPM(用 beats.json)
- 音效:转场音效、强调音效(叮/咚)、环境音
- 人声:口播/画外音/无,语速

### 6. 转化设计
- 结尾动作:关注引导/评论提问/下期预告/无(纯完播导向)
- 评论区钩子:文案里故意留的争议点/提问

## 拆解输出模板(deconstruction.json)

```json
{
  "source": {"url": "", "title": "", "duration": 0, "bpm": 0},
  "hook": {"type": "视觉冲击钩", "desc": "0-2s 小行星视角直接甩到第一人称", "why_works": ""},
  "segments": [
    {"start": 0, "end": 2.5, "shot": "小行星全景俯视", "action": "开场即全景视角冲击",
     "subtitle": "你敢信这是自拍?", "cut_on_beat": true, "energy": 8}
  ],
  "emotion_curve": "0-3s高冲击 → 3-8s悬念铺垫 → 8-15s连续小高潮 → 15s顶峰 → 结尾干脆",
  "sound": {"bgm": "", "sfx": "", "voice": ""},
  "formula": ["开头2s视觉炸点", "每3s内必切视角", "高潮在70%进度", "结尾无拖尾"],
  "transferable": "哪些手法可迁移到全景素材,哪些依赖原素材内容不可迁移"
}
```

## 拆解红线
- 不抄内容,只拆结构;`formula` 必须能脱离原视频独立成立
- 每段切镜判断必须有依据(帧变化/beat 对齐),不写"感觉"
- `transferable` 至少写出 2 条可迁移手法
